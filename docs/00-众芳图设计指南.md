## 1. 定位：它是什么，不是什么

### 1.1 原始需求

以中国女性为主题，重点表达四个维度：**女性风采展示、价值探索、魅力塑造、情感表达**；目标覆盖**中国全国广大地区**。

### 1.2 一句话定位

> **一部由她们自己落笔的当代群芳志，也是一个允许关系慢慢发生的地方。**

它同时是三样东西，且顺序不能颠倒：

1. **可读的志书**（内容层）：地域、人物、手艺、自述，未登录也能读；
2. **可通的书信**（关系层）：投书、回信、题跋，双向同意才发生；
3. **可见的雅集**（在地层）：同城、驻留、共学，线上关系落到线下。

### 1.3 明确不是（比「是什么」更重要）

| 不是 | 原因 |
| --- | --- |
| 不是相亲 / 婚介平台 | 一旦以「配对成功率」为目标，人物立刻变成条件卡，主语被收回；且婚介属特许经营，合规成本与调性双输（见 §17.3） |
| 不是美女图集 / 写真站 | 「图」的误读风险，见 §6.4 |
| 不是女性情感树洞 / 匿名倾诉社区 | 匿名情绪社区（一罐、0305 一类）留存高但关系浅，且极易滑向「暧昧经济」；本站要的是**署名**的表达 |
| 不是 MCN / 网红孵化 | 不做流量分配、不做涨粉工具、不做商单撮合 |
| 不是「非遗数字博物馆」 | 只展不连，会变成静态档案；必须有「她还在做事」的现在时 |

### 1.4 三类关系，权重递减

| 关系 | 说明 | 产品承载 |
| --- | --- | --- |
| **同好** | 因一门手艺、一个地方、一种活法而相遇 | 题跋、收进我的卷、跨区专题 |
| **同行** | 师承、合作、共学、互相引荐 | 立基档案、众芳亭访谈、众芳洲共学 |
| **伴侣** | 可能发生，但**不作为产品承诺**，也不做匹配算法 | 仅在双方都开启「可见」后自然发生；站方不介入、不撮合、不收费介绍 |

> **判断依据**：把「伴侣」写进产品目标，就会倒推出一整套凝视机制（颜值排序、滑动、在线状态、已读回执）。把它降为**副产品**，才保得住 §2 的三条硬约束。

## 2. 三条硬约束与「三问口诀」

后续所有决策的校验基准，任何机制上线前都要过这三条。

1. **主语在她**。女性是展示、探索、塑造、表达的主语，不是被观看、被题咏、被收纳的客体。凡让「访客凝视」成为默认关系的方案，一律否决。
2. **向前、主动、生成**。核心动词是生长与经营，不是失去、追怀、暂歇、等待。
3. **中国文化根脉**。符号须有典籍出处；不用基督教原罪叙事、不用日本现代情欲文学、不用凭空造的古风词。

> **三问口诀**：把名字、栏目或功能代入「**谁在动？谁在看？谁在命名？**」——答案必须是「她」。
> 这条口诀在 §9 设计每个机制、在 §21 校准现有代码时反复使用。

**衍生判据（v2 新增，用于产品机制）**：

| 判据 | 通过的样子 | 不通过的样子 |
| --- | --- | --- |
| 可见性是否对等 | 她能看到「谁读过我」 | 只有访客能窥看她，她不知道被谁看 |
| 主动权是否在她 | 她决定开不开放投书、收不收这条题跋 | 任何人可直接私信、可直接加好友 |
| 表达是否署名 | 自述、题名、印章、声音 | 匿名投稿、代笔、AI 代写不标注 |
| 关系是否可退出 | 一键收卷、真删除、可导出 | 注销后内容仍被索引、被转存 |

## 3. 为什么否掉「失乐园」（决策留档）

| 层面 | 问题 |
| --- | --- |
| 文化出处 | 「乐园」的三层指向（伊甸园 / 乌托邦 / 游乐场）无一落在中国传统根脉，违反 §2 第 3 条 |
| 语义内核 | 「被赐予 → 被逐 → 失去」与四个维度（展示 / 探索 / 塑造 / 表达）**全部反向**：它讲的是失去，站点讲的是生成 |
| 主语 | 「被逐」的主体是受害者，动作是被动语态，违反 §2 第 1、2 条 |
| 直觉 | 「园」的直觉是对的——问题不在「园」，在「失」 |

**结论**：否决，但保留「园」这个直觉，翻转出**造园**，于是有了《园冶》四工序（§10）与「她们自己造园」的立论。这一翻转是全案的起点。

## 4. 意象符号体系

### 4.1 四维度符号表（定案）

| 维度 | 首选意象 | 文化出处 | 语义 / 设计转译 |
| --- | --- | --- | --- |
| 风采展示 | **众芳**、灼灼、卿云 | 《离骚》「固众芳之所在」；《诗·周南·桃夭》「灼灼其华」；《卿云歌》「日月光华，旦复旦兮」 | 「众芳」天然是复数，是「她们」而非「她」，**从根上避开单一凝视**；卿云可做光色渐变系统 |
| 价值探索 | **木棉**、源泉、精卫 | 舒婷《致橡树》「作为树的形象和你站在一起」；《孟子·离娄下》「源泉混混……有本者如是」；《山海经》精卫填海 | 木棉是当代中国女性主体性最有力的文本，不柔媚、不依附；「有本」＝价值内生、不假外求 |
| 魅力塑造 | **织 / 经纬 / 锦**、窑变、造园 | 嫘祖始蚕、苏蕙《璇玑图》、《园冶》、瓷釉 | 「自己织就」把塑造的主动权交回本人；经纬直接变成栅格、编织纹理、卡片结构；窑变＝入窑同色、出窑万彩，不可预定也不可规训 |
| 情感表达 | **薛涛笺**、回文锦书、萱草、莲 | 薛涛自制桃色小笺写诗酬赠；苏蕙织回文诗；《诗·卫风·伯兮》「焉得谖草」；《西洲曲》「莲子清如水」 | 关键是「**她自己造了书写的载体**」——由她写，而非被写；萱草是中国本土的母亲花，比康乃馨更有根 |

### 4.2 补充判断

- **苏蕙《璇玑图》**与**薛涛笺**把「情感表达」与「技艺 + 文才 + 主动性」焊在一起，是「由她书写」的最佳典故，**比任何伤逝意象都贴题**。
- **莲**：《爱莲说》「中通外直，不蔓不枝，香远益清，亭亭净植」几乎逐字对应四个维度，是最稳的通用符号；但荷花 + 水墨极易落俗。**只取「中通外直」作结构隐喻，不做主视觉**。
- **「国香」可用作 slogan 备选**：《左传·宣公三年》「以兰有国香」，黄庭坚「兰之香盖一国，则曰国香」；配《孔子家语》「芝兰生于深谷，不以无人而不芳」，正好接上「价值不假外求」。

### 4.3 禁用符号（硬约束）

| 类别 | 禁用项 | 原因 |
| --- | --- | --- |
| 弃妇 / 伤逝 | 秋扇 / 团扇（班婕妤《怨歌行》）、秋风纨扇 | 弃妇意象，向后、被动 |
| 被逐 / 孤寂 | 嫦娥广寒 | 与「失乐园」同构 |
| 被凝视 | 洛神（《洛神赋》主体在曹植的凝视）、《女史箴图》式人伦教化 | 主语不在她 |
| 幽闭空间 | 闺阁 / 深院 / 后花园 / 绣楼 | 传统里是幽闭空间，非公共场域 |
| 灾祸归因 | 红颜 / 倾城 / 祸水 | 把女性写成灾祸因果 |
| 规训符号 | 缠足、贞节牌坊、宫 / 椒房 / 后妃安置 | 主语被收回 |
| 字根 | **失、怨、恨、闺、媚、残、瘦** | 一律避开，含「妖冶」「sultry」类语感 |
| 产品符号 | 左右滑卡、爱心火焰、在线小绿点、颜值评分、附近的人雷达 | 直接复制凝视机制 |

### 4.4 色彩与质感（定案方向）

色彩走**中国色：天青、月白、藕荷、缃、黛、朱砂**，纸绢 / 笺 / 手卷的温润明亮调；**不用伊甸园绿，不用深暗烛光夜场**。

视觉元素取：**手卷、薛涛笺、经纬 / 编织纹理、题跋、印章**；不做照片墙、不做网格头像流。具体色值与组件见 §15。

## 5. 四维度 → 产品能力映射

四个维度不是文案口号，必须各自有承载物，否则会退化成四个形容词。

| 维度 | 产品能力 | 页面 / 组件 | 可对标的成功产品机制 |
| --- | --- | --- | --- |
| 风采展示 | 人物卷：一张主图 + 一段自述 + 一段声音 + 一枚印 | `/person/[id]`、笺卡、卷轴 | Hinge 的 prompt 资料卡；小红书的图文笔记 |
| 价值探索 | 相地档案：来处、条件、源流、正在解决的问题 | `/region/[code]`、相地图 | 豆瓣日记；Substack 的长期写作 |
| 魅力塑造 | 立基档案：技艺序列、师承、工序、作品时间线 | 立基页、工序长卷 | Behance / Letterboxd 的作品档案 |
| 情感表达 | 题名 + 笺：她自拟标题、手写或语音、投书与回信 | 题名页、投书组件 | Slowly 的慢递书信；网易云乐评的共情密度 |

## 6. 定名：众芳图

### 6.1 放弃「甸」（用户提出，判断成立）

- **声调**：众(4) 芳(1) 甸(4)，首尾双去声下坠、收尾促；「众芳洲」4-1-1 平收略淡；**「众芳图」4-1-2 末字阳平上扬**，中文名最佳收尾。
- **异读**：甸单读 diàn；「沉甸甸」口语读 diān；古音另有 tián / shèng 等。现代汉语里最高频的三处是缅甸、草甸 / 沉甸甸、**伊甸园**——最后一个正是已否掉的「乐园」的字面用字。品牌联想不讲字源讲直觉。
- **语感**：古义为王畿郊甸，现代偏北地郊野、偏沉重。《春江花月夜》「芳甸」整句很美，单拎「甸」做站名撑不住。

### 6.2 众芳洲 vs 众芳图

| | 众芳洲 | **众芳图** |
| --- | --- | --- |
| 读音 | 4-1-1，平收、温润但略淡 | **4-1-2，上扬、响亮** |
| 根脉 | 《关雎》「在河之洲」；《九歌·湘君》「采芳洲兮杜若」 | 《周礼》「掌天下之图」；图经；仕女图长卷 |
| 全国尺度 | 洲 → 九州、五大洲，有量级 | 「掌天下之图，以掌天下之地」，**直接承载全国疆域** |
| 站点可用性 | 偏静、偏「思与待」；「洲 / 州」易写错，带地名 / 景区感 | 长卷、图谱、地域索引可直接变成信息架构与交互 |
| 风险 | 像实体园区，不像平台 | 须防「图集 / 写真」误读（见 §6.4） |

> **「洲」不是不好，是位置不对**：两个最著名出处，一个是《关雎》「君子好逑」的被观看视角，一个是《湘君》期约不遇的「思与待」；整体偏静、偏柔、偏等待。**留作社区 / 驻地 / 线下雅集子品牌名**，调性恰好。

### 6.3 「图」的三重传统（决定性依据）

1. **总揽天下**：《周礼·夏官·职方氏》「**掌天下之图，以掌天下之地**」；《地官·大司徒》「以天下土地之图，周知**九州**之地域广轮之数」；《史记·萧相国世家》萧何入咸阳独收「律令图书」。
   → 「图」在先秦两汉就是**承载全国疆域的载体**，用更雅、更准的方式解决了「覆盖广大地区」，且不带政治味。
2. **一地之志**：「图经」是早期地方志，「图即地图，经即地图的文字说明」，又称图志、图记，宋代编纂最盛，后与方志合流。
   → 「众芳图」天然读作一部**系统的当代群芳志**，而不是随手翻的画册。
3. **女性群像长卷**：仕女图本就是「以表现女子生活为主题」的独立画科；张萱《捣练图》按捣练、织线、熨烫**工序**在长卷上铺开十二人。
   → 织作工序、手卷移步换景，正好接住「织 / 经纬」与「滚动即游园」。

另：《说文》「图，画计难也」——「图」作动词是**谋划、蓝图**（「而后乃今将图南」），带主动建构的时态；「河出图，洛出书」又让它与「书」并列为文明元典。

> **一个字同时接住「全国」「群像」「志」「她自己落笔」，这是「洲」给不了的。**

### 6.4 唯一要防的误读（含规避动作）

「图」若被读成「图片 / 写真 / 美女图集」，就滑回被凝视的客体。规避不难，且是设计动作：

- 副名 / 栏目用「**众芳图志**」「**众芳长卷**」「**九州芳信**」把语义钉在「志与卷」，不钉在「图集」；
- 视觉走**手卷、笺、经纬、题跋、印章**，不做照片墙、不做网格头像流；
- 立一句精神文案：**「不是被画的仕女图，是她们自己落笔的长卷」**——直接把「谁执笔」翻过来；
- **结构化防御**：人物卷首屏是「自述 + 题名 + 声音」，图片为单张主图而非图集；不提供「全部照片」入口（见 §9 M2）。

## 7. 产品模型：三层结构

交友产品最常见的两种死法：**只有通、没有读**（资料卡空洞，只能靠脸和条件筛人，必然滑向凝视）；**只有读、没有通**（好内容没人回，作者得不到回应，半年后停更）。众芳图必须同时解决两者，所以做成三层。

| 层 | 名字 | 访客动作 | 登录要求 | 典型产品参照 |
| --- | --- | --- | --- | --- |
| L1 读 | 志 · 卷 | 读人物卷、逛地域、订花信 | 不需要 | 小红书（内容可被搜索与分享）、豆瓣（慢阅读） |
| L2 通 | 书 · 跋 | 投书、回信、题跋、收进我的卷 | 需要，且需双向条件 | Slowly（慢递）、Hinge（内容触发对话） |
| L3 见 | 洲 · 集 | 报名雅集、共学、驻留 | 需要，需实名与在册 | Meetup（兴趣线下）、Thursday（小规模线下） |

### 7.1 三层的转化关系

```
读（认识她） → 通（与她通信） → 见（和她一起做一件事）
      ↑                |                 |
      └──── 她的新卷 ←──┴──── 雅集产出 ←─┘
```

- **每层都能独立成立**：只读的用户也是有效用户（贡献搜索、分享、口碑）；不通也能留。
- **L2 不是 L1 的奖励**：不设「解锁」「等级」「付费才能发信」。L2 的门槛是**她的许可**，不是站方的付费墙。
- **L3 必须由她发起或共同发起**：站方只提供场地、保险、招募工具，不代替她组局。

### 7.2 为什么不直接做交友产品

| 维度 | 纯交友产品 | 众芳图 |
| --- | --- | --- |
| 供给 | 需要海量用户才有匹配效率，冷启动极难 | 30 个扎实的人就能成立，靠内容与地域长尾获客 |
| 单用户价值 | 匹配失败即流失 | 读到好内容即有价值，不依赖匹配 |
| 女性体验 | 私信骚扰与「照骗」是结构性问题 | 默认关闭投书、可见性对等、无排名，结构性降低骚扰 |
| 品牌寿命 | 与「单身状态」绑定，用户脱单即离开 | 与「她是谁」绑定，可长期积累成志书 |

> **结论**：用交友产品的**关系深度**（互信、慢节奏、有限供给），不用它的**筛选逻辑**（滑动、评分、条件过滤）。这是本站与所有同类产品的根本分界。

## 9. 核心机制十二条

每条机制都要能通过 §2 的三问。下表是总览，重点机制在后文展开。

| # | 机制 | 出处 | 规则（一句话） | 红线 |
| --- | --- | --- | --- | --- |
| M1 | **可见性对等** | 探探互喜 / 隐私设计 | 她可以看见「谁读过我的卷」，访客名录对她透明 | 不做「悄悄关注」「隐身访问」 |
| M2 | **先文后像** | Hinge prompt / 小红书笔记 | 首屏是自述、题名、声音；单张主图，无图集 | 不做九宫格、不做照片墙 |
| M3 | **她出题** | Hinge prompts | 她给自己的卷题名，并留一道「回信题」 | 站方不代拟标题、不提供「爆款标题」 |
| M4 | **有限供给** | Coffee Meets Bagel | 「花信」每候一封，只推一卷，不推无限流 | 不做下拉刷新、不做信息流无限加载 |

| M9 | **无榜** | Letterboxd | 无热搜、无粉丝数、无颜值分、无「附近的人」 | 任何形式的人气排序都禁止 |
| M10 | **在册认证** | Raya / 青藤 | 只认证「本人 / 手艺 / 机构」三类 | 不认证学历、收入、婚况、外貌 |
| M11 | **在地雅集** | Meetup / Thursday | 她发起、限 12 人、公开场地、可结伴 | 不做「一对一见面」撮合、不做酒局 |
| M12 | **可退出** | Hinge「为删除而设计」 | 一键收卷隐藏全部；注销即真删；可导出 | 不做「注销后内容仍可被搜索」 |

### 9.1 M1 可见性对等（本项目的定义性机制）

传统内容平台是**单向可见**：作者不知道谁在看。交友平台更糟：付费可以「看谁喜欢我」，把窥看变成商品。众芳图反过来：

- 每卷有「读过的人」名录，**她本人可见**，访客彼此不可见；
- 访客首次进入人物卷时明确提示：「她将看到你读过」；
- 她可对某个访客**关闭可见**（对方仍能读公开内容，但不再出现在她的名录里）。

> **为什么这条最重要**：它把「被看」从被动事实变成**双方知情的相遇**，一句话解决了全案的立论——不是不让看，而是**看得见彼此**。

### 9.2 M4 花信：有限供给怎么落地

- **节奏**：按二十四节气 + 七十二候，**每候（5 天）一封**；不按日推，避免日更压力。
- **内容**：一封花信 = 一卷 + 一段编者题跋 + 一个可参与的题目（如「你家乡的那棵树」）。
- **数量**：一封只推一个人、一个地方、一个问题。
- **订阅**：邮件 / RSS / 站内，不强制注册；可随时退订。
- **反模式**：不做「为你推荐」瀑布流，不做「猜你喜欢」，不做 push 轰炸。

### 9.3 M5 慢递：为什么必须延迟

即时通讯会把关系压成「回复速度竞赛」，并放大骚扰。24 小时延迟带来三个直接效果：

1. **筛掉随手撩**：愿意等一天的人，投书内容质量显著更高；
2. **给收信人缓冲**：她永远不必在情绪未备时回应；
3. **天然反骚扰**：无法连续轰炸，也无法要求「秒回」。

配套规则：无「正在输入」、无「已读」、无「在线」、无「最后活跃时间」。回信同样延迟 24 小时（可设置为 48 小时，给她更多空间）。

### 9.4 M9 无榜：可量化的红线

上线前逐条检查，任何一项出现在代码或设计稿里即驳回：

- [ ] 没有点赞总数、收藏总数、阅读量、粉丝数对外展示
- [ ] 没有「热门」「最受欢迎」「本周之星」榜单
- [ ] 没有颜值评分、身材标签、年龄排序
- [ ] 没有「附近的人」、没有实时定位
- [ ] 没有「谁看过我」的付费解锁（她本人免费可见）
- [ ] 搜索排序默认按**相关性与地域**，不按热度

### 9.5 M12 可退出：数据权利的具体承诺

| 动作 | 效果 | 时限 |
| --- | --- | --- |
| 收卷 | 全部内容与投书入口下线，名录清空，可随时开卷 | 即时 |
| 导出 | 导出全部自述、题名、题跋、投书为 Markdown + 图片包 | 24 小时内 |
| 注销 | 真删除（含备份轮转期内标记删除），不可恢复 | 立即生效，备份 30 天内清除 |
| 撤回单条 | 删除某条题跋 / 投书，对方侧同步消失 | 即时 |

## 10. 栏目骨架：相地 → 立基 → 借景 → 题名

### 10.1 出处校勘（重要纠正）

> **这四个词不是照抄《园冶》目录，是做的编排**：《园冶》全书十三篇（兴造论、园说、相地、立基、屋宇、装折、栏杆、门窗、墙垣、铺地、掇山、选石、借景）里**没有「题名」篇**，它出自**园林题匾传统**。「相地、立基、借景」是《园冶》篇名。

《红楼梦》十七回「大观园试才题对额」，贾政说：「偌大景致，若干亭榭，**无字标题，也觉寥落无趣，任有花柳山水，也断不能生色**」。

### 10.2 四工序内涵（定案）

| 工序 | 原义与出处 | 落到站点是什么 | 交互落点 |
| --- | --- | --- | --- |
| **相地** | 《园冶·相地》「**相地合宜，构园得体**」，「立基先究源头，疏源之去由，察水之来历」。分山林、城市、村庄、郊野、傍宅、江湖六类 | **价值探索**：先认清自己的来处、条件与地势再谈生长。**地域栏目整体挂在这一层** | 地域页、相地图、来处问答 |
| **立基** | 《兴造论》「凡造作，**必先相地立基**」；《立基》「凡园圃立基，**定厅堂为主**」 | **魅力塑造**：定骨架与主脑，不是往外表贴装饰。「三分匠、七分主人」——**主导权九成在「能主之人」，这是「主语在她」的古典版** | 技艺档案、工序长卷、师承 |
| **借景** | 全书压轴篇：「**夫借景，林园之最要者也**」，分远借、邻借、仰借、俯借、应时而借；「**俗则屏之，嘉则收之**」 | **风采展示 + 跨地域联动**：打破围墙把园外山河纳进构图，且**由她决定什么进画面** | 跨区专题、主题策展、「嘉则收之」的取舍声明 |
| **题名** | 非《园冶》篇目，出园林题匾传统（见 §10.1） | **情感表达 / 自我定义**：没名字就「不能生色」；**命名即赋义，谁题名，园子就属于谁** | 自拟标题、题跋、印章签名 |

> 四步连起来是 **认地 → 立骨 → 取景 → 赋名**，正好是一个人把自己建成一座园的过程，也是站点的内容漏斗。

### 10.3 两套体系的嵌套关系（关键观点）

**地域体系与四工序是嵌套，不是并列**：

- 地域栏目整体归在 **相地**（认来处）；
- 跨区专题按主题把不同地方的人放进同一构图，走的是 **借景**（「俗则屏之，嘉则收之」）；
- 每篇末尾留一块由**她本人题名**，是 **题名**；
- 而这整套三层架构本身就是 **立基**。

### 10.4 每条内容必须集齐的四件东西

| 要素 | 对应工序 | 缺失后果 |
| --- | --- | --- |
| 来处（地域 + 条件） | 相地 | 变成悬浮的「人设」 |
| 一门在做的技艺 / 正在做的事 | 立基 | 变成静态档案 |
| 她主动放进来的外部参照 | 借景 | 变成孤立个案 |
| 她自己起的标题 | 题名 | 变成被描述的客体 |

> **内容准入规则**：四件缺一，不进首页、不进花信。这条规则同时是选题清单与编辑 SOP。

## 11. 地域架构

### 11.1 三个总目的分工（定案）

| 名称 | 定位 | 语义 | 页面 |
| --- | --- | --- | --- |
| **九州芳信** | 地域总目 | 「信」＝音信、花信，各地寄来的一封封信 | `/fangxin` |
| **四方众芳** | 人物群像库 / 索引 | 按方位筛 | `/fangxin/renwu` |
| **海内芳踪** | 行旅、在地探访、时间线 | 「踪」是走过的路，动态的 | `/fangxin/zong` |

### 11.2 分层原则

> **别按 34 个省平铺**（太碎，且极易滑成「某地出美女」的花名册），**也别把古九州当唯一分层**（与今省界不对应，考据成本高）。
> 用**文化地理大区**做中层，**8–12 个**，底下再落省市与本人。

### 11.3 两个示例的取舍

**陕西 → 未央宫：字挑得极好，但请把「宫」字去掉。**

「未央」出《诗·小雅·庭燎》「夜如何其？夜未央」，朱熹注「央，中也」，即**未半、未尽**；汉瓦当「长乐未央」是吉语——最好的状态不是全盛，而是**兴盛还在后头**，与「众芳图」的蓝图义、「向前、生成」完全同调。但「宫」自带禁闭与后妃安置，会把主语收回去。

→ 栏目叫 **「未央」或「长安未央」**，可挂**上官婉儿**（长安，掌诏命）、**薛涛**（原籍长安入蜀，串起巴蜀）。

**湖北 → 黄鹤楼：建议换。**

崔颢「昔人已乘黄鹤去」、李白「故人西辞黄鹤楼」，最好的诗都在写**人去、送别、乡愁**，又是「失」的结构，与已否掉的「失乐园」同调。湖北自家的楚辞更贴：**「芳洲」**（《湘君》「采芳洲兮杜若」）或 **「汉广」**（《诗·周南·汉广》「汉有游女，**不可求思**」——「不可求」是她拒绝被求）。若坚持黄鹤楼，取李白那句的 **「烟花三月」**（出发、下行、向前），别取「昔人已去」。

### 11.4 八大区示范（储备，可扩至 8–12 区）

| 大区 | 栏目名 | 地标 / 典故 | 可挂的叙事 | 挂哪一维 |
| --- | --- | --- | --- | --- |
| 关中（陕） | **未央** | 长乐未央瓦当、汉长安 | 上官婉儿掌诏命、薛涛入蜀 | 相地 |
| 荆楚（鄂湘） | **芳洲** | 《湘君》采芳洲兮杜若、汉水 | 采芳相赠、不可求思 | 题名 |
| 齐鲁（鲁） | **漱玉** | 济南漱玉泉、李清照《漱玉词》 | 自撰《金石录后序》，以词立言 | 题名 |
| 中原（豫） | **溱洧** | 《诗·郑风》上巳「赠之以勺药」 | 先秦男女自由相谑、相赠 | 借景 / 情感 |
| 吴越（江浙沪） | **机杼** | 松江黄道婆、棉纺织革新 | 技术主体性；接「织 / 经纬」 | 立基 |
| 巴蜀（川渝） | **浣花** | 成都浣花溪、薛涛笺 | 自己造笺写诗酬赠，由她书写 | 题名 |
| 岭南（粤桂琼） | **高凉** | 冼夫人（谯国夫人，《隋书》立传） | 保境安民、主动治理 | 立基 |
| 云贵 / 陇右 | **驿路 · 春风** | 奢香夫人开水西驿道；反用「春风不度玉门关」 | 主动开路、把外面连通进来 | 借景 |

### 11.5 编排红线

> **地标当成「她讲自己来处的坐标」，别当成给人贴地域标签或排座次的依据**——否则既容易招来刻板印象争议，也把「谁在看」又交回给访客了。

每个条目里放**她自己的叙述、手艺、声音和自拟的标题**，那正好就是「题名」这一维在起作用。

### 11.6 覆盖全国靠信息架构，不靠品牌名

> **「覆盖全国」不该由品牌名承担，交给信息架构。** 地域板块叫「九州芳信」「四方众芳」「海内芳踪」，栏目按地域铺开，比在名字里硬塞一个「国」字稳得多，也更好做内容扩展。

### 11.7 大区与「关系层」的联动

| 场景 | 规则 |
| --- | --- |
| 同城雅集 | 只有与她在同一大区的人能收到「众芳洲」通知；不显示精确位置 |
| 地域专题 | 跨区组稿由编辑发起，作者可拒绝，不标注「代表某地」 |
| 搜索 | 支持「城市 + 手艺」长尾（如「潮州 木雕」），结果按相关性而非热度 |
| 空白地区 | 显式呈现「此地尚未立卷」，并开放自荐；**不用占位假人填充** |

## 14. 数据模型

以**人**为主键，关系与内容都是它的延伸。字段设计同时是权限设计。

```ts
type RegionCode = 'guanzhong' | 'jingchu' | 'qilu' | 'zhongyuan'
  | 'wuyue' | 'bashu' | 'lingnan' | 'yungui-longyou'
  // 可扩至 12 区：西北、东北、青藏、港澳台

type Chapter = 'xiangdi' | 'liji' | 'jiejing' | 'timing'

type Visibility = 'public' | 'readers' | 'letterwriters' | 'private'

interface Person {
  id: string
  name: string
  selfTitle: string          // 自拟标题 → 题名
  region: RegionCode
  city?: string              // 可选，精确到城市为止
  craft: string[]            // 技艺 / 正在做的事
  lineage?: string[]         // 师承，可选
  narrative: string          // 自述，第一人称，现在时
  voice?: { src: string; seconds: number; transcript?: string }
  portrait?: { src: string; alt: string; credit?: string }  // 单张主图
  chapter: Chapter           // 主挂维度
  prompt?: string            // 她留给访客的回信题
  visibility: {
    voice: Visibility
    letters: 'open' | 'on-request' | 'closed'
    city: boolean
  }
  seals: Seal[]              // 印章 / 认证
  createdAt: string
  status: 'draft' | 'review' | 'published' | 'archived'
}

interface Note {              // 笺：一次内容发布
  id: string
  personId: string
  title: string              // 由她题名
  body: string
  media: Media[]             // 单图或短影像，不做图集
  topic?: string
  publishedAt: string
}

interface Letter {            // 投书：单向，24h 延迟
  id: string
  fromId: string
  toPersonId: string
  body: string
  sentAt: string
  deliverAt: string          // = sentAt + 24h
  readAt?: string            // 仅收信人可见，不回传给发信人
  replyId?: string
  status: 'queued' | 'delivered' | 'replied' | 'declined' | 'expired'
}

interface Inscription {       // 题跋：公开的长评，须署名
  id: string
  personId: string
  authorId: string
  anchor: string             // 针对哪一句（必填）
  body: string               // ≥ 30 字
  seal?: string
  accepted: boolean          // 她可「不收此跋」
  createdAt: string
}

interface Gathering {         // 众芳洲雅集
  id: string
  hostId: string             // 必须是在册卷中人
  region: RegionCode
  city: string
  topic: string
  capacity: number           // 上限 12
  venue: { name: string; public: true }
  safety: string[]           // 安全须知版本号
  startsAt: string
  status: 'draft' | 'open' | 'full' | 'done' | 'cancelled'
}

interface Seal {              // 在册认证
  type: 'person' | 'craft' | 'institution'
  issuer: string
  verifiedAt: string
}
```

### 14.1 刻意不建模的字段

| 不建 | 原因 |
| --- | --- |
| `likes`、`views`、`followers` | 制造排行的原料（§9.4） |
| `rating`、`attractiveness` | 颜值评分，绝对禁止 |
| `lat/lng`、`lastActiveAt`、`online` | 定位与在线状态，骚扰与焦虑来源 |
| `income`、`education`、`maritalStatus` | 条件筛选，婚介逻辑 |
| `matchScore` | 算法配对，违背 §1.4 |

> **评审方法**：任何新增字段，先问「它会不会被用来给人排序或给人贴价签」，会则不进模型。

### 14.2 由 `region` 聚合的索引

- 地域页：`Person.where(region).where(status === 'published')`，按 `updatedAt` 倒序；
- 跨区专题：按 `chapter` + 主题标签聚合，**不按地域数量排名**；
- 空缺：某区人数为 0 时渲染「尚未立卷」，不隐藏、不造假。

## 16. 内容与文案规范

### 16.1 三条写作原则

1. **第一人称、现在时**：她写「我在做」，不写「她曾……」；
2. **具体优于形容**：写「一天拉坯四十个，废掉三十个」，不写「匠心独运」；
3. **可核对**：人名、地名、技艺名、年份必须可查；不确定就标注「据口述」。

### 16.2 禁用与慎用词

| 级别 | 词 | 说明 |
| --- | --- | --- |
| **禁用** | 失、怨、恨、闺、媚、残、瘦（含「妖冶」「sultry」「纯欲」） | 违 §2 |
| **禁用** | 女神、名媛、白富美、小姐姐、颜值、身材、初恋脸、擦边 | 物化与标签化 |
| **禁用** | 征婚、优质单身、脱单、配对成功率 | 婚介话术 |
| **禁用** | 惊鸿一瞥、一眼万年、令人心动、被看见的美 | 凝视视角 |
| **慎用** | 传承、匠心、守艺人 | 易空泛，须配具体事实 |
| **慎用** | 东方、国风、古风 | 易廉价化，须有出处 |
| **推荐** | 在做、正在、我来、我决定、我题 | 主动语态 |

### 16.3 写作模板

**自述（150–300 字）**

```
我是___，在___做___。
我开始做这件事，是因为___。
现在我每天___，最难的是___，我还在解___。
如果有人想聊，可以问我：___。
```

**题名（≤ 12 字）**：由她自拟，编辑不得代改。示例：「浣花溪边的第九年」「我把外婆的纹样拆开重织」。

**题跋（≥ 30 字）**：必须锚定原文某句 + 一个具体回应 + 自己的身份，禁止「写得好」「支持」。

**投书（≤ 500 字）**：说明「我是谁、为什么写给你、我在做什么」，禁止模板化问候与外貌评价。

### 16.4 审核规则

| 内容 | 审核方式 | 不通过的样子 |
| --- | --- | --- |
| 人物卷 | 人工复核（校书） | 无自述、无题名、图不对题、疑似盗图 |
| 题跋 | 机器初筛 + 举报驱动 | 广告、人身攻击、外貌评价、无锚点 |
| 投书 | 收信人自主 + 机器反骚扰 | 群发、索取联系方式、金钱话题 |
| 匿名求助 | 单独通道、强制人工（是否设立**待确认**，见 §22.2） | 具体自杀 / 自伤内容必须转人工干预流程 |
| 雅集 | 人工审核 + 安全须知确认 | 非公开场地、一对一约见、酒精主题 |

### 16.5 生成式 AI 使用规则（待确认）

- 允许用 AI 辅助**排版、翻译、图片修复**，须在页脚标注；
- **禁止**用 AI 生成「人物」「自述」「声音」；
- 禁止 AI 换脸、AI 生成「想象中的她」；
- 若使用 AI 生成配图，须按《人工智能生成合成内容标识办法》做显式 + 隐式标识。

## 17. 安全、隐私与合规

### 17.1 威胁模型

| 威胁 | 场景 | 防御机制 |
| --- | --- | --- |
| 骚扰 / 纠缠 | 私信轰炸、索取联系方式 | 投书默认关闭（M6）、24h 慢递（M5）、无法群发、拉黑即全站生效 |
| 人肉 / 定位 | 通过地名、口音、活动照片反推住址 | 仅显示到大区，城市字段可选；雅集只显示公开场地；照片剥离 EXIF |
| 盗图 / 冒名 | 搬运他人作品立卷 | 在册认证（M10）、人工复核、原图比对、举报下架 |
| 杀猪盘 / 诈骗 | 建立情感信任后诱导投资 | 禁止金钱话题（机器识别）、禁止导流外部社交、风险提示、异常账号限流 |
| 未成年人 | 冒充成年人参与 | 18+ 门槛、实名核验、未成年人内容一律不收录 |
| 恶意题跋 | 贬损、外貌评价、引战 | 必须锚定原文 + ≥30 字 + 她可「不收此跋」、无盖楼 |
| 内容外泄 | 截图搬运到其他平台 | 水印（她的印 + 站名）、禁止右键下载原图、投书内容禁止截图提示 |

### 17.2 隐私默认值

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 人物卷 | 公开 | 立卷即同意公开自述与主图 |
| 声音 | 关闭 | 需她主动开启 |
| 投书 | 关闭 | 需她主动开启，可选「需申请」 |

### 17.3 合规清单（中国大陆运营，须法务复核）

| 事项 | 要求 | 落地 |
| --- | --- | --- |
| 账号实名 | 后台实名、前台自愿（《网络安全法》） | 手机号 + 身份证核验，仅存哈希与核验结果 |
| 个人信息 | 最小必要、单独同意、可撤回、可删除（《个人信息保护法》） | 敏感项（声音、精确位置）单独弹窗同意；提供导出与删除 |
| 未成年人 | 18+ 限制（《未成年人保护法》《未成年人网络保护条例》） | 注册年龄门槛 + 核验；发现即冻结并通知监护人流程 |
| 算法 | 若上线任何推荐 / 排序，须备案并可关闭（《互联网信息服务算法推荐管理规定》） | 当前设计无推荐流；如新增须先备案 |
| 内容生态 | 审核、举报、应急处置（《网络信息内容生态治理规定》） | 举报入口全站可达；7×24 应急联系人；日志留存 ≥ 6 个月 |
| 生成式 AI | 备案与标识（《生成式人工智能服务管理暂行办法》及标识办法） | 仅辅助用途，显式标注；不生成人物 |
| 婚介资质 | 有偿介绍婚恋对象可能构成婚介服务 | **不做介绍、不收费撮合**；文案避免「婚恋」「相亲」 |
| 线下活动 | 大型群众性活动需安全许可（1000 人以上） | 单场限 12 人，不触发；仍购场地责任险 |
| 等保 | 二级等保备案 | 上线前完成定级备案 |
| 数据出境 | 不涉及 | 全量数据境内存储 |

> **合规底线一句话**：**不做撮合、不收介绍费、不存精确位置、不生成人物**。这四条同时是法律风险与技术风险的防火墙。

## 18. 冷启动与增长

### 18.1 冷启动：先做 30 个人，不做 3 万个账号

交友产品死于「供给不足 → 体验差 → 更少供给」的负循环；内容社区则可用**少量高质量供给**启动。众芳图走后者。

| 阶段 | 目标 | 动作 |
| --- | --- | --- |
| 0 → 1 | 12 个扎实的卷 | 编辑逐一访谈、代录（她口述、校书整理、她终审题名），覆盖 6 个大区 |
| 1 → 10 | 30 卷 / 8 区 | 每卷配一篇长访谈（众芳亭）+ 一组工序图；开始发花信 |
| 10 → 100 | 自荐通道开启 | 「此地尚未立卷」页开放自荐；老卷中人推荐制（每人 2 个名额） |
| 100+ | 线下 | 每季 3–5 场众芳洲，优先在有 5 卷以上的城市 |

**种子选择标准**：正在做事（不是「曾经」）、有可展示的工序、愿意署名、愿意回信。**不要**先找 KOL 或颜值博主——那会把内容结构带偏。

### 18.2 供给节奏

- **花信**：每候一封，全年 72 封，可提前排期到季度；
- **新卷**：每周 1–2 卷，宁少勿滥（四要素齐备才发）；
- **专题**：每季一个「借景」跨区专题，围绕一个具体问题（如「你家乡的那棵树」「一件修了三次的东西」）。

### 18.3 获客：靠搜索长尾，不靠投放

| 渠道 | 做法 | 说明 |
| --- | --- | --- |
| SEO | 标题模板「{人名} · {手艺} · {城市}｜众芳图」；地域页覆盖「{城市} {手艺} 女性」 | 静态预渲染天然友好；每卷独立 URL 与结构化数据 |
| 分享 | 笺卡分享图（题名 + 一句话 + 印章），不裁人脸 | 分享落地到人物卷，不落到首页 |
| 邀请 | 卷中人推荐制，2 个名额 / 人 | 保证质量，制造稀缺 |
| 邮件 / RSS | 花信订阅 | 唯一主动触达渠道，可退订 |
| 线下 | 雅集、书展、市集 | 二维码落到具体一卷，不落首页 |
| 合作 | 非遗机构、地方文旅、独立书店 | 只做内容共建，不做流量置换 |

**增长红线**：不买量、不做信息流广告、不做「附近的人」地推、不用 AI 生成假人填充、不做擦边素材投放。

### 18.4 留存设计

| 钩子 | 机制 | 注意 |
| --- | --- | --- |
| 花信 | 每候一封，固定节奏 | 不做每日 push |
| 回信 | 投书 24h 后送达，形成期待 | 不用红点焦虑 |
| 题跋被收 | 她「收下」时通知作者 | 不做「被赞」提示 |
| 专题征稿 | 每季一个问题 | 不排名、不评选 |
| 雅集 | 同城 | 人数少、门槛低 |

## 19. 指标与实验

### 19.1 北极星

> **每周完成「投书 → 回信」的双向连接对数。**

选它的理由：它同时要求「有人愿意读」（内容质量）、「她愿意开」（安全感）、「信写得好」（表达质量），无法靠刷量伪造，也不会诱导凝视。

### 19.2 指标树

| 层 | 指标 | 说明 |
| --- | --- | --- |
| 北极星 | 周双向连接对数 | 见上 |
| 供给 | 通过复核的新卷数 / 周；四要素齐备率 | 质量优先 |
| 消费 | 单卷读完率；花信打开率；搜索落地页跳出率 | 不看停留时长 |
| 表达 | 题跋数 / 卷；题跋被收率；首条题跋转化 | 表达质量 |
| 关系 | 投书开启率；投书回复率；平均往返轮次 | 深度而非数量 |
| 在地 | 雅集成行率；复参率 | 线下质量 |
| 健康 | 举报率；P0/P1 处置时长；注销率 | 安全底线 |

### 19.3 反指标（出现即视为设计失败）

单次会话时长、滑动 / 刷新次数、私信总量、点赞总数、日活／月活比（会诱导做焦虑机制）、「颜值相关」点击率。

### 19.4 实验原则

- 只做**降低门槛**的实验（如题跋编辑器、投书引导），不做**提高刺激**的实验（无限流、倒计时、红点）；
- 任何 A/B 实验上线前过 §2 三问 + §9.4 红线清单；
- 涉及可见性与隐私的改动**不做实验**，直接按最保守方案执行。

## 附录 B 决策日志

| 轮次 | 议题 | 关键判断 | 结论 |
| --- | --- | --- | --- |
| 一 | 「失乐园」能否表达主旨 | 三层指向无一落在中国传统；语义核「被赐予→被逐→失去」与四维度全撞；但「园」的直觉对 | 否决；翻转出「造园」；建立意象符号体系与三条硬约束 |
| 二 | 「众芳」+ 斋 / 亭 / 岛 / 国 | 四字不是同一把尺子；亭是「点」不是「域」；「国」有女儿国联想；两部群芳谱证明亭 / 斋只是署名空间 | 要「域」不要更大的建筑；首推「众芳甸」；「众芳亭」降级 |
| 三 | 甸 / 洲 / 图 择一 | 「甸」音理三问题（声调、异读、伊甸园撞词）；「图」在先秦即承载全国疆域，且兼「志」与「长卷」 | **定案「众芳图」**；副名「众芳图志」；「洲」留作社区子品牌 |
| 四 | 四工序内涵 + 地域栏目 | 纠正「题名」非《园冶》篇目；未央宫去「宫」、黄鹤楼换楚辞；地域按文化地理大区分层，不按省平铺 | 四工序＝认地→立骨→取景→赋名；三总目分工；八大区示范；覆盖全国交给信息架构 |
| 五 | 产品形态与关系机制（v2 新增） | 纯交友产品的筛选逻辑必然倒向凝视；但交友产品的互信机制（双向、慢、有限、具体、可退出）值得全盘借用 | **定案「人物志 × 慢关系」三层结构**；关系目标去配对化；十二条机制；无榜、无滑动、无付费解锁 |

**贯穿全案的三条主线**：主语在她 / 向前生成 / 中国根脉；以及三次「翻转」——**「失乐园」→「造园」**、**「被画的仕女图」→「她们自己落笔的长卷」**、**「滑动筛选」→「她授予可见」**。
